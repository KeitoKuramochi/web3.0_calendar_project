## ユーザーフロー

### 先生フロー

```
1. Googleログイン
2. 初回のみ：ロール選択 → 「先生」を選択
3. 初回のみ：研究室名を入力して研究室を作成 → 参加コードを取得
4. 先生ダッシュボードへ遷移
5. カレンダーUIまたはチャットで空き枠を設定する
6. 学生からの面談リクエストが届くと承認待ちリストに表示される
7. 承認 or 差し戻し（差し戻し時は代替日程を入力）
8. チャットまたは直接入力で学生に課題を割り当てる
9. 学生ダッシュボードで各学生の進捗・課題状況を確認する
```

### 学生フロー

```
1. Googleログイン
2. 初回のみ：ロール選択 → 「学生」を選択
3. 初回のみ：参加コードを入力して研究室に参加
4. 学生ダッシュボードへ遷移
5. 先生のカレンダーで空き枠を確認する
6. チャット画面を開いてAIボットに相談する
   └ botが解決できると判断した場合 → チャットで解決して終了
   └ 面談が必要と判断した場合 → 準備会話を経てリクエスト送信へ
7. 面談が必要な場合：希望日時を選んで先生にリクエストを送る
8. 先生が差し戻した場合：代替案から選んで再リクエストする
9. 承認されると日程が確定（メール通知）
10. 自分の課題を確認し、完了したらチャットから完了報告する
```

## データ

| 概念 | 説明 |
|---|---|
| ユーザー（users） | Google ID・名前・メール・role（teacher / student） |
| グループ（groups） | 研究室名・作成者・参加コード |
| グループメンバー（groupMembers） | group_id・user_id・role |
| チャットログ（chatLog） | 全会話の生データ（永久保存・削除しない） |
| メモリ（memory） | AIが書くパーソナルメモ（JSON自由形式・ユーザーごと） |
| 空き枠 | 先生が設定する日時・所要時間のエントリ |
| 面談リクエスト | 学生から先生への面談依頼・ステータス・希望日時・代替案 |
| 課題 | 先生が学生に割り当てるタスク・期限・完了状態 |

memoryのJSON構造例（概念レベル）:
- ui_settings: 表示順・表示形式などのUI設定
- preferences: 好みの時間帯・相談パターン
- auto_rules: 自動承認ルール（先生側）
- last_summary: 前回会話の要約

## 制約・前提

- MVPスコープは研究室1つ（先生1人+学生N人）
- 全会話はchatLogに永久保存する。削除機能はMVP対象外
- DURING（当日リアルタイム）はMVP対象外
- Discord / LINE 連携はMVP対象外
- オンチェーントークンはMVP対象外（DBで管理）
- Phase 1はダミーデータで動作し、DBや外部APIには接続しない
- Phase 2以降でインフラを接続する。Phase 1のUIを壊さずに接続する
- `RESEND_API_KEY` 未設定時はメール送信をスキップしコンソールに記録する
