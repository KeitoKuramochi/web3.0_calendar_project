# Evaluation Criteria

Evaluatorが使う評価基準。この基準に基づいて合格・不合格を判定する。

---

## 1. 機能性

| 評価項目 | 確認方法 | 合格基準 |
|---|---|---|
| ユーザーが目的を達成できるか | Playwrightで主要フローを操作 | フローが最初から最後まで完走できる |
| 主要操作が実際に動作するか | ボタン・フォームを実際に操作 | クリック・入力・送信が機能する |
| スタブ・未接続の機能がないか | UIを操作して反応を確認 | "TODO"・"coming soon"・空の関数が残っていない |

**判定ルール:**
- スタブや仮実装が残っている → 即不合格
- クリックしても何も起きない → 即不合格

---

## 2. UI品質

| 評価項目 | 確認方法 | 合格基準 |
|---|---|---|
| 見た目が破綻していないか | Playwrightでスクリーンショット | 要素が重なる・はみ出すなどがない |
| 余白・色・文字サイズが自然か | 目視確認 | 極端に大きい/小さい要素がない |
| スマホ表示（375px）で崩れないか | Playwrightでビューポート375px設定 | レイアウトが保たれている |
| テンプレート的なAIデザインに偏りすぎていないか | 目視確認 | ダミーテキストや明らかなプレースホルダーがない |

**判定ルール:**
- スマホ幅でレイアウトが崩れる → 不合格
- ダミーテキスト（"Lorem ipsum"等）が残っている → 不合格

---

## 3. エラー耐性

| 評価項目 | 確認方法 | 合格基準 |
|---|---|---|
| 入力ミス・失敗時に壊れないか | 空送信、不正入力を試す | アプリがクラッシュしない |
| ユーザーに分かるエラー表示があるか | エラーを意図的に発生させる | エラーメッセージが表示される |
| ブラウザAPIが使えない場合でも落ちないか | コードを確認 | `navigator.share()` 等に条件分岐がある |

**判定ルール:**
- 空送信でアプリがクラッシュする → 不合格
- エラーが発生しても何も表示されない → 不合格

---

## 4. 実装品質

| 評価項目 | 確認方法 | 合格基準 |
|---|---|---|
| TypeScriptの型が適切か | コードを確認 | `any` が使われていない |
| anyを使っていないか | `grep -r 'any' src/` | ヒットしない（新規追加分） |
| 不要な依存関係を追加していないか | `git diff package.json` | Plannerが承認した依存のみ |
| 大規模リファクタリングをしていないか | `git diff --stat` | 変更ファイル数が妥当 |

**判定ルール:**
- 新規に `any` が追加されている → 不合格
- 無許可で `package.json` に依存が追加されている → 即不合格・人間に報告

---

## 5. タスク分離

| 評価項目 | 確認方法 | 合格基準 |
|---|---|---|
| 1TASKの範囲を超えていないか | git diff で変更範囲確認 | 対象TASKと無関係なファイルが変更されていない |
| commitが1TASK単位になっているか | `git log` | 1TASKにつき1commit |
| STATUS.md と MVP_TASKS.md が実態と一致しているか | ファイルを読む | 完了条件の照合結果と一致 |

**判定ルール:**
- 無関係なファイルが大量に変更されている → 不合格・理由を説明
- docs/STATUS.md が更新されていない → 不合格

---

## 総合判定

| 判定 | 条件 |
|---|---|
| ✅ 合格 | 上記5カテゴリすべてで不合格項目がない |
| ❌ 不合格 | 1つでも不合格項目がある |

**「概ね良い」は合格ではない。すべての条件を満たして初めて合格。**
