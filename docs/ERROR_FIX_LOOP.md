# Error Fix Loop

Generatorがbuildエラーに遭遇したときの対処手順。

## 基本ルール

- 最大3回まで修正を試みる
- 3回失敗したら作業を停止し、人間に状況を報告する
- 修正ごとに `npm run build` を実行して結果を確認する

## 修正手順

### ステップ1: エラーを読む

```bash
npm run build 2>&1
```

エラーメッセージを全文読む。以下を特定する:
- エラーが発生しているファイルと行番号
- エラーの種類（型エラー、モジュール未検出、構文エラーなど）

### ステップ2: 原因を特定する

エラーメッセージだけで判断できない場合は、エラー箇所のファイルを読む。
グローバルな find / grep での探索は最終手段。まず局所的に読む。

### ステップ3: 修正する

- 修正は最小限にする
- エラーに直接関係しない変更は加えない
- `any` で型エラーを逃げない

### ステップ4: 再ビルド

```bash
npm run build 2>&1
```

成功 → commitへ進む
失敗 → 試行カウントを1増やしてステップ1へ戻る

## 試行カウント

| 試行 | 状態 | 備考 |
|---|---|---|
| 1回目 | — | |
| 2回目 | — | |
| 3回目 | — | 失敗なら人間に報告 |

## 人間への報告テンプレート（3回失敗時）

```
## build失敗 — 人間の介入が必要

### 対象TASK: TASK-XXX

### 最後のエラーメッセージ:
（エラー全文）

### 試みた修正:
1. 1回目: 〇〇を変更した → まだ同じエラー
2. 2回目: 〇〇を変更した → 新しいエラーが出た
3. 3回目: 〇〇を変更した → まだ失敗

### 現在のファイル状態:
（変更中のファイル一覧）

### 推測される原因:
（自分の判断を超えている理由）
```

## よくあるエラーパターン

### TypeScript型エラー

- `Type 'X' is not assignable to type 'Y'` → `types/index.ts` または対象ファイルの型定義を読む
- `Property 'X' does not exist on type 'Y'` → 型定義を確認して正しいプロパティ名を使う
- `any` で逃げない

### モジュール未検出

- `Cannot find module '...'` → importパスのタイポ、または存在しないファイルを参照している
- 大文字小文字が違う場合もある（macOSは大文字小文字を区別しないが、本番環境は区別する）

### Next.js固有

- `AGENTS.md` に「This is NOT the Next.js you know」という警告がある
- `node_modules/next/dist/docs/` にガイドがある
- App RouterのAPIはPages Routerと異なる
