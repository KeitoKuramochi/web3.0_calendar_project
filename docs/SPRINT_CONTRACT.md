# Sprint Contract

> このファイルはPlannerが各TASKの完了条件を記入する。GeneratorとEvaluatorが参照する。

## 方針

各TASKを始める前に、何を作るかを明確にする。
完了条件はEvaluatorが実際のブラウザ操作またはコンソール確認で検証できる形で書く。

## 完了条件の書き方ルール

**良い例（具体的で操作確認できる）:**
- `localhost:4321/teacher` を開くと週ビューカレンダーが表示される
- 「承認」ボタンをクリックすると面談ステータスが「確定済み」に変わる
- D1のchatLogテーブルにレコードが追加されている（Wranglerコンソールで確認）

**悪い例（曖昧・確認不能）:**
- いい感じに表示される
- 適切に処理される
- エラーハンドリングが実装されている

## ルール

- 1つでも完了条件を満たさない場合、そのTASKは不合格
- 不合格の場合、EvaluatorはGeneratorに戻す修正プロンプトを作成する
- GeneratorはEvaluatorから戻された修正プロンプトを優先的に対処する
- `npm run build` が通らない状態でコミットしない

**完了条件:**
