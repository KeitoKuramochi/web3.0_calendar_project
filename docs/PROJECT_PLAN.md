# Project Plan

## アプリの目的

研究室の先生と学生をつなぐ「進捗報告伴走ボット」。
AIボットが学生の相談を会話形式で受け付け、解決できるものはその場で解決し、先生との面談が必要なものは準備を整えてからスムーズに日程調整まで完結させる。

## 対象ユーザー

**学生（送り手）:**
- 進捗報告・方針相談・課題の詰まりを先生に相談したい大学院生・学部生
- 面談の依頼メールを書くのが億劫で、相談が後回しになりがちな学生

**先生（受け手）:**
- 複数の学生を抱え、質の低い相談に時間を取られたくない指導教員
- 空き枠の管理や連絡調整を効率化したい教員

## ユーザーが達成できること

- 学生: AIとの会話で相談内容を整理し、botで解決できるものはその場で解決できる
- 学生: 面談が必要な場合、準備が整った状態で先生に日程調整リクエストを送れる
- 学生: 先生からの課題を確認し、完了報告をチャットから送れる
- 先生: 空き枠をカレンダーUIまたは自然言語チャットで管理できる
- 先生: 準備が整った学生の面談リクエストだけが届くため、精査コストが下がる
- 先生: 学生ごとの進捗・課題状況をダッシュボードで把握できる
- 両者: 会話履歴がAIの記憶（memory）に蓄積され、使うたびに提案精度が上がる

## MVPの範囲

Phase 1（ダミーデータ版）でUIとUXを動かし、Phase 2でインフラ接続、Phase 3でbot知能化を行う。

研究室1つ（先生1人+学生N人）の運用を前提とする。

**Phase 1 — ダミーデータでUIを動かす**
1. プロジェクト初期設定（Astro + React on Cloudflare Pages + Hono Workers）
2. ランディングページ（ログイン前の説明）
3. ロール選択画面（先生 / 学生）
4. 先生ダッシュボード（カレンダー・承認待ちリスト・学生課題一覧）のUI
5. 学生ダッシュボード（先生カレンダー・自分の課題・チャット導線）のUI
6. チャット画面（先生・学生共通・AIなしのエコーbot）

**Phase 2 — インフラ接続**
7. Cloudflare D1 + Drizzle ORM セットアップ
8. Google OAuth 認証
9. オンボーディング（ロール選択・研究室作成・参加コード）
10. 先生：空き枠管理（D1保存・カレンダー反映）
11. 学生：面談リクエスト → 承認・差し戻しフロー
12. 課題管理（先生が割り当て・学生が完了報告）

**Phase 3 — bot知能化**
13. Gemini Flash 2.0 チャット接続（会話継続）
14. chatLog 永久保存 + memory 自動更新
15. 先生チャットでの空き枠自然言語設定
16. 学生チャットでの相談 → bot解決 or 面談準備フロー
17. Cron通知（Cloudflare Cron + Resend メール）
18. Workers AI 埋め込み + Cloudflare Vectorize RAG
19. bot学習（自動承認ルール・学生傾向のmemory蓄積）

## 将来機能（MVP外）

- Discord / LINE 連携
- 当日リアルタイムサポート（DURING フェーズ）
- 振り返り・フィードバック自動収集（AFTER フェーズ）
- オンチェーントークン（現在はDBで管理）
- マルチ研究室・複数先生対応
- 準備ポートフォリオ公開機能
